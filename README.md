# Teknova Trainings — بوابة التسجيل

## الملفات
- **الصفحات:** `index.html` (الرئيسية `/`)، `modes.html` (اختيار النمط `/modes`)، `tracks.html` (المسارات `/tracks`)، `training.html` (تفاصيل التدريب `/trainings/:id`)، `register.html` (التسجيل `/register`).
- **الإعدادات والبيانات:** `config.js` (الإعدادات المركزية: الأنماط والمدن والمسارات ورقم واتساب ورابط Apps Script)، `trainings-data.js` (المصدر المركزي لبيانات التدريبات ومستوياتها وخططها).
- **المنطق:** `site.js` (عرض الصفحات التسويقية وصفحات التدريبات)، `app.js` (منطق نموذج التسجيل في صفحة `/register` فقط)، `Code.gs` (واجهة Google Apps Script الخلفية).
- **التنسيق والأصول:** `styles.css` (نظام التصميم الموحّد)، `logo.svg` (الشعار).
- **إعدادات النشر:** `_redirects` (Cloudflare Pages / Netlify)، `vercel.json` (Vercel)، `.gitignore`.

## إعداد ربط Google Sheets

1. افتح جدول التسجيلات الرسمي:
   `https://docs.google.com/spreadsheets/d/1ejE1sAti0_OVRn82iyPyNSk7l6Dz3J60RIXUQG1CDLg/edit`
2. من الجدول اختر **Extensions → Apps Script**.
3. استبدل محتوى ملف `Code.gs` في محرر Apps Script بالكود الموجود في هذا المشروع، ثم احفظ.
4. من قائمة التشغيل اختر الدالة `setup` وشغّلها مرة واحدة، ووافق على صلاحيات الوصول إلى جدول Google Sheets عند ظهور طلب الموافقة. الدالة لا تحذف أو تعيد كتابة الصفوف السابقة؛ تنشئ ورقة `Registrations` عند عدم وجودها وتضيف عناوين الأعمدة الناقصة إلى يمين العناوين الموجودة.
5. اختر **Deploy → New deployment → Web app**.
6. اجعل **Execute as: Me**، و**Who has access: Anyone**، ثم Deploy ووافق على الصلاحيات.
7. انسخ رابط Web App الذي ينتهي عادةً بـ `/exec`.
8. افتح `config.js` واستبدل `PASTE_APPS_SCRIPT_WEB_APP_URL_HERE` في قيمة `endpoint` بالرابط الفعلي، ثم أعد نشر ملفات الموقع على الاستضافة.
9. عند تعديل `Code.gs` لاحقاً، افتح **Deploy → Manage deployments → Edit → New version → Deploy**.

**رابط Web App لا يمكن توليده من ملفات المشروع وحدها.** يجب أن ينشره مالك حساب Google الذي يملك صلاحية تحرير جدول التسجيلات.

## سلوك التسجيل
- لا تعرض الواجهة نجاحاً إلا بعد وصول استجابة JSON تتضمن `ok: true` ورقم تسجيل.
- يرسل المتصفح طلباً بسيطاً من نوع `text/plain` لتجنب طلب CORS التمهيدي.
- يحمي الزر من النقر المتكرر أثناء الإرسال، ويرسل `requestId` ثابتاً عند إعادة المحاولة بعد انقطاع الاتصال، ويمنع Apps Script حفظ الطلب نفسه مرتين.
- تُشتق المسارات المتاحة من `config.js`، ويتحقق Apps Script أيضاً من معرفات النمط والمدينة والمسار.
- لا تُرسل مدينة في التسجيل الأونلاين.
- لا يفتح واتساب تلقائياً. بعد نجاح الحفظ تظهر شاشة النجاح وزر يفتح محادثة `https://wa.me/963981890957` برسالة عربية ديناميكية جاهزة.

## النشر

الموقع ثابت بالكامل (HTML + CSS + JS) بلا خطوة Build، لذا يمكن نشره كما هو على أي استضافة ملفات ثابتة.

### Cloudflare Pages
1. ارفع محتوى مجلد `teknova` (ملفات المشروع مباشرة) إلى مستودع Git أو اربط المستودع بـ Cloudflare Pages.
2. في إعدادات المشروع:
   - **Framework preset:** None
   - **Build command:** اتركه فارغاً (لا توجد عملية بناء).
   - **Build output directory:** `/` (جذر مجلد `teknova`).
3. ملف `_redirects` يُقرأ تلقائياً من Cloudflare Pages ويحافظ على المسارات التالية:
   - `/register` → `/register.html`
   - `/modes` → `/modes.html`
   - `/tracks` → `/tracks.html`
   - `/trainings/:id` → `/training.html`

### Netlify / Vercel
ارفع المجلد كما هو أيضاً. يعمل `_redirects` على Netlify، ويعمل `vercel.json` على Vercel بنفس قواعد التوجيه.

## ملاحظات مهمة
- لا يحتوي `config.js` على مفاتيح سرية؛ يحتوي فقط على عنوان Web App العام ورقم واتساب العام.
- من الأفضل أن يكون الوصول إلى Web App مضبوطاً على Anyone كي يستطيع الزوار إرسال التسجيلات. لا تمنح أي شخص صلاحية تحرير الجدول؛ صلاحية التحرير تبقى لحساب مالك Apps Script.
- لم يتم تضمين رابط Web App لأن نشره يتطلب الدخول إلى حساب Google الخاص بمالك الجدول. يجب إجراء اختبار كتابة حي بعد النشر قبل اعتبار التكامل مفعّلاً.
